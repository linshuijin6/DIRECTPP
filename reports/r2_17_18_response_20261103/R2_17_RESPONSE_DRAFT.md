# Response to Reviewer 2, Comment 17

Thank you for highlighting the need to document how the comparators were adapted to MRI-to-PET synthesis and how comparison fairness was established. We agree that using the same evaluation metrics is insufficient: input information, subject assignments, preprocessing, optimization, checkpoint selection, and computational budgets must also be distinguished. We therefore separate the documented revision experiments from the incompletely recovered historical comparisons.

For the documented revision comparisons, DIReCT++, the clinical regression U-Net, SwinUNETR, and the retrained single-tracer DIReCT models use the same frozen cohort of 1,857 subjects and the same subject-level two-fold assignments. The held-out folds contain 929 and 928 subjects, respectively. The models reuse the same preprocessed MRI/PET tensors rather than independently recreating the splits or preprocessing. The pipeline includes LPI orientation, MRI-based foreground cropping, MRI histogram normalization, padding/cropping to \(160\times192\times160\), 1-mm spacing, intensity normalization, and scaling. Missing-tracer placeholder images are excluded from target losses and evaluation. The resulting out-of-fold evaluation includes 1,598 valid FDG and 1,365 valid AV45 targets. Full-volume SSIM, PSNR, MSE, and MAE are computed using the same definitions, with SSIM window size 7 and data range 1, PSNR maximum value 1, and predictions clamped to [0,1]. Brain-mask measurements are a separate analysis and are not mixed with these full-volume results.

The adaptations and training settings are as follows:

| Comparator | Adaptation and available inputs | Optimization and evaluation endpoint |
|---|---|---|
| SwinUNETR | The recovered implementation is MONAI's **3D SwinUNETR**, rather than an implementation identified solely by the original manuscript's “Swin-UNet” label. It has one MRI input channel, one continuous PET output channel, and feature size 48. It is adapted from segmentation to paired PET intensity regression by using an MSE objective rather than a segmentation-label objective. Independent models are trained for each tracer and fold. Its prediction branch receives MRI only. | Adam, learning rate \(10^{-5}\), batch size 1, AMP, activation checkpointing, and 200 epochs in each executed revision run. Epoch 200 is the fixed evaluation endpoint; no held-out checkpoint selection is used. |
| Single-tracer DIReCT | Four independent tracer/fold models perform 3D MRI-to-PET rectified-flow learning with the velocity target PET−MRI and MSE loss. The models receive patient-description embeddings and tracer-text embeddings. Patient embeddings are shared with the frozen DIReCT++ inputs; tracer prompts follow the documented Single encoding protocol, so this is not a comparison differing only in the number of output tracers. | Adam, learning rate \(2.5\times10^{-5}\), batch size 1, AMP, and training through 200 epochs. Fixed endpoints are epoch 165 (primary) and epoch 200 (secondary). The time variable is set to zero from zero-based epoch 140 onward. |
| Clinical regression U-Net | An independent four-level 3D U-Net directly regresses PET from MRI. The same eight clinical values used in the DIReCT++ descriptions—age, sex, weight, CDR, MMSE, GDS, FAQ, and NPI-Q—are supplied numerically, together with tracer identity. A 10→64→256 MLP modulates the bottleneck through FiLM. It uses neither BiomedCLIP nor flow/diffusion sampling. Clinical numeric standardization is fitted on the training fold only. | Adam, learning rate \(2.5\times10^{-5}\), batch size 1, AMP, and direct PET MSE summed over valid tracers. Training continues through 200 epochs, with fixed epoch-165 primary and epoch-200 secondary endpoints; monitored held-out losses do not select checkpoints. |

The clinical regression comparator specifically addresses unequal access to patient information. Its fields are checked against the actual DIReCT++ descriptions and underlying frozen table rather than merely sharing the same variable names. This controls the available input values, while deliberately changing how those values are encoded. It does not establish that the historical clinical fields were free of upstream imputation, nor does it isolate a single architectural component. At the matched epoch-165 endpoint, the full-volume SSIM means for DIReCT++ versus this comparator are 0.921129 versus 0.900311 for FDG and 0.884408 versus 0.860412 for AV45. These are results of the documented revision runs, not a reconstruction of every original Figure 2 baseline.

We also clarify the limits of the historical baseline evidence. Recovered conditional diffusion code adapts the network to 3D MRI-to-PET synthesis by concatenating MRI with the noisy/current PET estimate, predicting one PET channel, and supplying patient/tracer embeddings through cross-attention. However, the available candidate code and its alternative sampling settings are not conclusively bound to the original Figure 2 DDIM results. The final implementations, adaptation details, and run-to-result links for the historical CycleGAN, SegGuidedDiff, and plain 3D RF comparisons remain insufficiently documented. In particular, neither a method name nor its source application establishes whether the actual local implementation was 2D or 3D, how anatomical guidance was obtained, or which training budget produced the reported result. We therefore do not certify those historical rows as fully controlled comparisons or claim that all comparators were MRI-only.

Finally, the documented settings are **fixed experimental recipes**, not evidence that every model received an identical hyperparameter search or reached its individually optimized best configuration. Complete historical search records and equal tuning effort cannot be established from the available material. Even the revision experiments have explicit differences: SwinUNETR is MRI-only and evaluated at epoch 200, whereas the primary DIReCT++/clinical-U-Net/Single comparison uses epoch 165; their architectures, tracer organization, and per-update costs also differ. Equal epoch counts would not establish equal GPU-hour or optimization budgets. We consequently restrict fairness claims to the verified common cohort, splits, preprocessed inputs, evaluation protocol, and specified fixed endpoints, and do not retain the unrestricted claim that all baselines had identical tuning effort or training budgets.
